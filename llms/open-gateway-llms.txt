# GSMA Open Gateway

> GSMA Open Gateway is the mobile industry's operator-commitment and certification layer for network
> APIs, run by the GSM Association from London. Launched at MWC Barcelona on 27 February 2023 with 21
> operator groups and eight universal network APIs, it is the go-to-market wrapper around CAMARA, the
> Linux Foundation-hosted Telco Global API Alliance that actually authors the OpenAPI definitions.
> GSMA sits above the value chain rather than in it: it signs operators and channel partners to a
> memorandum of understanding, certifies implementations against CAMARA service APIs and TM Forum
> Operate APIs, and publishes which certified APIs are live in which markets.

Important for machine consumers: **GSMA operates no callable API and publishes no OpenAPI under its
own name.** Every `servers[0].url` in the specifications below is `{apiRoot}/<api-name>/<version>`,
where `apiRoot` is supplied by a certified operator, aggregator or channel partner (Aduna, Vonage,
Infobip, Sinch, Twilio, Nokia, AWS, Bridge Alliance, Telefonica, Orange, Deutsche Telekom and
others). There is no GSMA host to call, no GSMA API key, and no GSMA self-serve signup. GSMA does run
a first-party developer sandbox at https://open-gateway.gsma.com/sandbox. Both gsma.com and
open-gateway.gsma.com sit behind a Cloudflare bot challenge that returns 403 to automated clients.

Per the GSMA's Q1 2026 Open Gateway update: 81 operator groups and 61 channel partners covering 292
networks and about 80 percent of global mobile connections have signed, with 237 certified API assets
drawn from 33 CAMARA tagged released APIs and 280 API instances commercially launched across 85
networks in 50 markets.

## How to call these APIs correctly

- [API conventions](conventions/open-gateway-conventions.yml): `x-correlator` echo, page/perPage pagination, the closed request contract, the ErrorInfo envelope, and the absence of any idempotency key.
- [Authentication](authentication/open-gateway-authentication.yml): a single `openIdConnect` scheme named `openId` on 21 of 22 specs, plus `notificationsBearerAuth` for callback sinks.
- [OAuth scopes](scopes/open-gateway-scopes.yml): 38 purpose-built consent scopes in `api-name[:resource]:action` form.
- [Error catalogue](errors/open-gateway-problem-types.yml): CAMARA `{status, code, message}` on `application/json` — NOT RFC 9457 problem details.
- [Lifecycle](lifecycle/open-gateway-lifecycle.yml): URI-path versioning, twice-yearly meta-releases, no Sunset header, no status page, no SLA.
- [Changelog](changelog/open-gateway-changelog.yml): the CAMARA meta-release train.
- [Webhooks and events](asyncapi/open-gateway-webhooks.yml): CloudEvents over `sink`/`sinkCredential`; no AsyncAPI document exists.
- [Conformance](conformance/open-gateway-conformance.yml): what these APIs do and do not conform to.
- [Sandbox](sandbox/open-gateway-sandbox.yml): GSMA API Sandbox and the Orange CAMARA Playground.
- [Data model](data-model/open-gateway-data-model.yml): the shared Device identifier and the TMF931 relational core.
- [Domain security](security/open-gateway-domain-security.yml) and [vulnerability disclosure](security/open-gateway-vulnerability-disclosure.yml).

## Caveats for agents

- Do not attempt to call an endpoint from these specifications without an operator-supplied
  `apiRoot`. The default `http://localhost:9091` in the upstream specs is a placeholder.
- With a three-legged access token the subscriber is implied by the token; sending the `device`
  object as well returns `422 UNNECESSARY_IDENTIFIER`.
- There is no idempotency key anywhere in CAMARA. Writes — `createPayment`, `createSession`,
  subscription creates, TMF931 orders — are not safe to blindly retry.
- Errors are not RFC 9457. Parse `{status, code, message}` on `application/json`.
